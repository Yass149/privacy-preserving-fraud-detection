Collapse and recovery under DP-SGD

The headline result: combining DP-SGD with standard loss-based class weighting removes fraud detection entirely rather than degrading it, and data-level oversampling restores it. Reproduced on three seeds and on a second dataset.

Control experiments

"What broke" shows that the model collapses. These three controlled experiments are the evidence for why — each varies exactly one thing against the seed-42 configuration.

Already walked through in the presentation slides — kept here for Q&A reference, not re-narrated live.
Control 1 — remove the class weight entirely
If clipping cancels the weight, this should change nothing

A tenfold change in how the objective punishes minority errors produces, to three decimal places, the same model.
Control 2 — isolate DP's cost from oversampling's cost
Same 5× oversampling fix, with and without DP-SGD attached
Non-private, no oversampling0.727 recall · F1 0.691
Non-private + 5× oversampling0.609 recall · F1 0.766
DP-SGD + 5× oversampling0.743 recall · F1 0.626
Oversampling alone is not harmful — it trades recall for precision and improves Macro F1 (0.691→0.766). The headline finding's F1 damage (0.691→0.626) is attributable to DP specifically, not to the remedy chosen for it. Source: results/metrics/training_metrics_baseline_ctrl_oversampled.json.
Control 3 — loosen the clip
max_grad_norm swept on the reweighted run (log scale)
Recall recovers as the clip loosens — the model's ranking quality falls over the same range. The recall is real; the model is worse.
ℹ
The asymmetry is the argument. The same knob swept over the oversampling fix moves recall by only 0.005. Clipping is decisive for a remedy that works through gradient magnitude, and nearly inert for one that works through gradient count.

1A GRU turns five transactions into one score
The architecture's temporal half — not a generic MLP over flattened features
src/model_arch.py · lines 46–66
46class TemporalGatedAggregator(nn.Module):
47 def __init__(self, latent_dim, hidden_dim):
48 super(TemporalGatedAggregator, self).__init__()
49 self.gru = nn.GRU(latent_dim, hidden_dim, batch_first=True)
50
51 def forward(self, x_sequence):
52 output, _ = self.gru(x_sequence)
53 return output[:, -1, :]
54
55class FraudDetector(nn.Module):
56 def __init__(self, input_dim, latent_dim, hidden_dim):
57 super(FraudDetector, self).__init__()
58 self.encoder = FeatureBottleneckEncoder(input_dim, latent_dim)
59 self.aggregator = TemporalGatedAggregator(latent_dim, hidden_dim)
60 self.classifier = nn.Linear(hidden_dim, 2)
61
62 def forward(self, x_sequence):
63 # 3D sequence passed directly to match the RACC2 training environment
64 encoded_seq = self.encoder(x_sequence)
65 temporal_features = self.aggregator(encoded_seq)
66 return self.classifier(temporal_features)
TemporalGatedAggregator wraps a single nn.GRU; FraudDetector.forward() chains the encoder's per-transaction embeddings through it and keeps only the final hidden state — output[:, -1, :] — as the representation of the whole 5-transaction window. That is the model reading a motif across transactions, not scoring one transaction in isolation.

Line 149 sets a real 10× loss weight on fraud. Eight lines later, line 161 hands the model to Opacus's make_private() with a per-sample gradient clip — which renormalises every sample's gradient to the same L2 budget regardless of how the loss weighted it. This is the single interaction the whole thesis is about (Finding 01): the weight is genuine in the objective and cancelled before the optimiser ever sees it.

tiebreak="txid" (line 111) is the historical, contaminated ordering: kept in the code only because it reproduces the run that exposed the leak — a model with zero real signal still reached 0.48 fraud recall under it. tiebreak="hash" (line 114), now the default, orders tied rows by a hash decorrelated from txId; the leaked recall collapses to exactly 0.000 under it, on every seed tried.
